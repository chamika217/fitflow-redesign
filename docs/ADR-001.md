# ADR-001: FitFlow Cross-Platform Architecture

- **Status:** Accepted
- **Context:** FitFlow requires iOS, Android and web support, high performance, real-time social features, nutrition/workout data, AI personalization and secure user accounts.
- **Decision:** Use Flutter clients, NestJS backend, PostgreSQL, Redis, FastAPI AI service and Auth0.
- **Why:** Balances cross-platform delivery, performance, security, AI capability, maintainability and cost for a mid-sized team.
- **Alternatives rejected:**
  - React Native – strong option but less consistent web strategy.
  - Kotlin Multiplatform – strong native performance but higher complexity and less mature web UI.
  - SwiftUI – excellent Apple UX but poor fit for Android/web.
  - MongoDB / Firebase – useful alternatives but less suitable as the core relational system of record.
- **Consequences:** Team must learn Dart/Flutter; two backend languages to maintain; native health integrations may need Swift/Kotlin; more services than a monolith.
- **Mitigation:** Keep the AI service small and isolated, use shared OpenAPI contracts, automate CI/CD, document interfaces, use native modules only when necessary.
